# Nexus MCP — Claude Code Agent Instructions

You are connected to **Nexus MCP OSS** ([github.com/brian-Lab-0/nexus-mcp-oss](https://github.com/brian-Lab-0/nexus-mcp-oss)), the observability and token-optimization layer for AI agents built by OpenBnet.

Nexus is running at `http://127.0.0.1:8787`. Use the MCP tools below throughout this session to reduce token cost, detect drift, and record your work for offline analysis.

---

## Session startup (do this first)

### 1. Register yourself

```json
POST /nexus/agents
{
  "id": "claude-code-<project-slug>",
  "name": "Claude Code — <project-name>",
  "platform": "claude-code",
  "instanceId": "<machine-or-workspace-id>",
  "version": "claude-opus-4-7",
  "tags": ["<repo>", "<task-type>"]
}
```

Or via MCP: `nexus_register_agent`

### 2. Fetch the guide (first session or when unfamiliar)

```text
nexus_agent_guide  { format: "markdown" }
```

### 3. Declare your session budget

```text
nexus_context_budget  { sessionId: "<id>", action: "set", budget: 80000 }
```

## During every task

### Compress long prompts before sending to LLM

Call `nexus_compress_prompt` when prompt > 200 tokens or contains multiple sections. Token savings: 35–94% depending on prompt type.

```json
{ "prompt": "<full-system-prompt>", "task": "<current-task-description>", "aggressiveness": "medium" }
```

### Read files through the cache

Use `nexus_read_cached` instead of raw file reads. First read returns full content; subsequent reads of unchanged files return only a summary — saving the full token cost.

```json
{ "path": "/absolute/path/to/file.ts" }
```

### Check for symbols before reading whole files

Use `nexus_list_symbols` to see what's in a file, then `nexus_get_symbol` to extract only the function or class you need.

### Analyze each step for drift

Call `nexus_analyze_step` every 2–3 steps. If `needsCorrection` is true, apply the `correctionPatch` before continuing.

```json
{
  "agentId": "<id>",
  "step": 3,
  "output": "<your last output>",
  "taskGoal": "<original task>",
  "previousOutputs": ["<step n-1>", "<step n-2>"]
}
```

### Emit activity events

Signal task lifecycle so Nexus records and monitors your work.

```text
started    → when task begins
running    → on each significant step
completed  → when done
failed     → on unrecoverable error
```

Include `sessionId`, `taskId`, `tokensInput`, `tokensOutput`, `tokensSaved` in metadata when known.

### Track token usage

```text
nexus_context_budget  { sessionId: "<id>", action: "track", tokens: <used-this-step> }
```

## Session end

### Distill the session

Compress the full conversation into a ~45-token cold-start snapshot so the next session restores context without replaying history.

```text
nexus_distill_session {
  agentId: "<id>",
  messages: [<full conversation>],
  taskGoal: "<task>",
  sessionStandardTokens: <baseline>,
  sessionNexusTokens: <actual>,
  steps: <n>
}
```

### Segment episodes

```text
nexus_segment_episodes  { sessionId: "<id>", activities: [<activity list>] }
```

### Generate handoff

```text
nexus_session_handoff  { sessionId: "<id>" }
```

Inject the returned summary at the start of the next session instead of replaying history.

## Monitoring your impact

```text
nexus_benchmark_summary   — aggregate tokens saved, cost saved, per-ability latency
nexus_benchmark_events    — raw per-call event log
nexus_cache_stats         — file cache hit ratio
```

All interactions are also recorded to `data/sessions/<sessionId>.jsonl` for offline analysis.

Fetch a full session analysis:

```text
GET /nexus/recordings/<sessionId>/analysis
```
